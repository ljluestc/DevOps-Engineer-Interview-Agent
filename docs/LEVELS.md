# 难度分级定义（LEVELS）

每道题必须标注一个难度级别。分级的依据是**考察的能力层次**，而非「这个知识点本身难不难」。

| 标记 | 级别 | 考察重点 | 典型问法 | 期望回答 |
|---|---|---|---|---|
| 🟢 | 初级 | 概念认知、基础命令、常见现象 | 「什么是 X？」「怎么查看 Y？」 | 能给出正确定义与基本用法 |
| 🟡 | 中级 | 原理理解、排障思路、配置实践 | 「X 为什么这样？」「Y 出问题怎么排查？」 | 讲清原理 + 分步排查 + 实操命令 |
| 🔴 | 高级 | 架构权衡、复杂排障、性能优化 | 「X 和 Y 怎么选？」「大规模下 Z 的瓶颈与解法？」 | 多方案对比 + trade-off + 实战数据 |
| ⚫ | 资深 | 体系设计、跨团队推动、技术决策 | 「你怎么设计/推动 X？」「失败案例与复盘？」 | 系统性思考 + 影响力 + 量化结果 |

---

## 各级能力锚点

### 🟢 初级（0–2 年）
- 熟悉 Linux 常用命令、文件权限、基础网络概念。
- 会用 Docker 跑镜像、用 kubectl 操作 Pod。
- 能照文档完成部署、基础监控查看。
- **不要求**：架构设计、复杂排障、性能调优。

### 🟡 中级（2–5 年）
- 理解系统/网络原理，能独立排查常见故障（CPU/IO/网络/容器）。
- 能编写 Ansible Playbook、CI 流水线、Prometheus 告警规则。
- 熟悉 K8s 核心对象与排障。
- **不要求**：跨系统架构权衡、组织级推动。

### 🔴 高级（5–10 年）
- 能在多方案间做技术权衡并落地（如存储选型、调度架构）。
- 主导过重大故障排查或架构改造，有量化结果。
- 理解大规模下的瓶颈与优化路径（千节点 K8s、GPU 集群等）。
- 能给团队定规范、做技术评审。

### ⚫ 资深（10 年+ / 专家）
- 设计跨团队/跨域的技术体系（多集群、多活、AI 平台）。
- 推动技术战略与组织落地，影响多个团队。
- 具备「技术判断力」：在不确定性中做正确取舍。
- 能培养人、沉淀方法论。

## 标注建议

- 同一知识点可出多道题覆盖不同级别。例：
  - 🟢「什么是负载均衡？」
  - 🟡「LVS 的 NAT/DR/TUN 区别与适用？」
  - 🔴「千兆流量下 L4/L7 负载均衡的选型与扩容路径？」
- 避免级别通胀：能靠记忆回答的不要标 🔴。
- 行为/架构类题多数落在 🔴/⚫。
