# 题目标准化规范（STANDARD）

> 本文件是 ops-interview 的「宪法」。所有面试题**必须**遵循本文定义的模板与质量要求。
> 目的：让每一题都「讲清楚概念 + 有排障思路 + 有权衡判断 + 有落地经验」，而非一句结论。

---

## 一、为什么需要标准化

运维面试的难点不在「背多」，而在「讲透」。一个高质量题目应当能考察候选人：

1. **概念是否清晰**（关键词能不能用一句话讲明白）
2. **原理是否理解**（为什么这样设计，边界在哪）
3. **排障是否有方法**（出问题怎么分步定位）
4. **权衡是否到位**（方案 A vs B 的取舍）
5. **实战是否有经验**（踩过什么坑，怎么解的）

标准化模板 forcing function 地保证以上五点都被覆盖。

---

## 二、题目模板（强制）

每道题使用如下 Markdown 结构：

```markdown
### Q<编号>. <一句话题目>

- **难度**：🔴 高级
- **关键词**：kubernetes, CRI, 容器运行时, OCI
- **概念速记**：
  - **CRI（Container Runtime Interface）**：kubelet 与容器运行时之间的 gRPC 接口，解耦 K8s 与具体运行时（containerd / CRI-O）。
  - **OCI**：开放容器倡议，定义镜像规范（image-spec）与运行时规范（runtime-spec），runc 是其实现。
- **问题**：kubelet 如何通过 CRI 管理容器？为什么需要这一层抽象？
- **参考答案**：
  1. kubelet 通过 CRI 的 `RuntimeService` / `ImageService` 两个 gRPC 服务调用运行时；真正创建容器由底层的 OCI runtime（如 runc）完成。
  2. 抽象价值：K8s 不必绑定 Docker，可替换运行时（containerd 更轻、CRI-O 面向安全）；升级运行时不影响 K8s 控制面。
  3. 实操：dockershim 已在 1.24 移除，生产推荐 containerd；排查时看 `crictl`/`ctr` 而非 `docker`。
- **易错点 / 面试官关注**：
  - 混淆 CRI（接口）与 OCI（规范）、与具体运行时（containerd/runc）。
  - 不知道 dockershim 已废弃。
- **延伸**：Q50、[basics/04-kubernetes-concepts.md](basics/04-kubernetes-concepts.md)
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `### Q<编号>` | ✅ | 标题用一句话概括题目；编号在**所属文件内**连续 |
| **难度** | ✅ | 🟢初级 / 🟡中级 / 🔴高级 / ⚫资深（见 [LEVELS.md](LEVELS.md)） |
| **关键词** | ✅ | 3–6 个核心概念，便于检索与关联 |
| **概念速记** | ✅ | **本项目特色**：用一两句人话把关键词讲清楚（定义 / 作用 / 与其他概念关系）。可多条 |
| **问题** | ✅ | 具体的面试问法 |
| **参考答案** | ✅ | 分点，含 trade-off / 实战命令 / 边界 |
| **易错点 / 面试官关注** | ✅ | 真实误区或深度追问点 |
| **延伸** | 推荐 | 关联题号、basics 文档、外部链接 |

---

## 三、质量要求

1. **概念速记必须「能当定义用」**：新人读完应能向别人复述。避免「详见下文」式甩锅。
2. **参考答案要「有深度、有边界」**：不只说「用 X」，要说「什么时候用 X，代价是什么，替代方案 Y 何时更优」。
3. **命令要可验证**：涉及 Linux/K8s 命令，给出真实可用示例（如 `kubectl describe node`）。
4. **不编造、不照搬**：引用外部资料注明来源；优先基于官方文档与一手经验。
5. **术语中英文并存**：首次出现的关键词给出英文（如 Pod 反亲和性 Pod Anti-Affinity）。
6. **难度别通胀**：能靠记忆回答的不要标 🔴；需要架构权衡的才配 🔴/⚫。

---

## 四、编号规则

- 编号在**每个模块文件内**独立连续（如 `kubernetes/kubernetes-questions.md` 内从 Q1 编起）。
- 跨文件引用时用「文件名 + 题号」或「主题 + Q 号」，避免全局重号混乱。
- 若需全局唯一 ID，可在编号后加前缀（如 `K8S-Q12`），但文件内保持一致即可。

## 五、反例 vs 正例

❌ **反例（太表面）**：
```
Q. K8s 网络怎么实现？
A. 用 CNI 插件，比如 Calico、Flannel。
```
问题：没解释 CNI 是什么、为什么需要、各插件差异。

✅ **正例（标准化）**：见上方模板示例。

## 六、basics/ 与 modules/ 的分工

- **basics/**：深度概念文。把一类关键词系统讲透（定义、原理图、对比表、常见误区）。**不直接当面试题**，而是面试前的「地基」与题目的「概念速记」溯源。
- **modules/**：具体面试题。每题的「概念速记」可从 basics/ 提炼一句话；需要展开时通过「延伸」链回 basics/。

两者通过「延伸 / 引用」互链，形成「概念 → 题目」的网状结构。
